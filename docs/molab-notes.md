# Notes: what had to be worked around (molab, RTX PRO 6000 Blackwell, torch 2.11 + CUDA 13)

Kept so a future run (or a reviewer) can see why the setup code looks the way it does.

## Environment
- **Fresh process per stage.** The notebook process imports `torch`/`transformers` before setup installs more packages; Python caches those imports and "is X installed" checks, so in-process stages fail with errors like "requires accelerate". Every GPU stage therefore runs as `python -m c44 <stage>`.
- **Do not let installs replace molab's torch.** FlashWorld's dependencies pull in a second torch (2.15) into the venv. `setup_env.remove_shadow_torch()` removes it. vggt and gsplat are installed with `--no-deps`.
- **gsplat JIT needs a matched CUDA toolkit.** molab ships nvcc 13.3 next to CUDA 13.0 headers; CCCL refuses that mix ("compiler and toolkit headers are incompatible") and the CUDA 13 layout puts `<nv/target>` under `include/cccl`. `setup_env` installs a private CUDA 13.0 nvcc + headers matching torch and points the build at them. A failed earlier build leaves a stale ninja state, so the JIT cache is cleared first.
- **gsplat 1.5.3 vs FlashWorld.** In `rasterization(packed=True, backgrounds=...)` gsplat 1.5.3 asserts a background vector, while FlashWorld passes `[C, D]`. `flashworld_gen.py` wraps FlashWorld's rasteriser with `packed=False` (same renders). The wrapper also composites backgrounds itself.
- **Qwen2.5-VL** is loaded with a plain `.to(device)` (no `accelerate` dependency).

## Data
- `DL3DV-GS-960P` holds both `3DGS/<subset>/<hash>.zip` (the Gaussian model) and `imgs_undist/<subset>/<hash>.zip` (images only). Indexing must use `3DGS/` only.
- The NPR weights were saved from `nn.DataParallel` (keys start with `module.`).
- 3DGS `cameras.json` stores the original resolution (~3850×2133) with fx/fy but no cx/cy.

## Benchmark design decisions
- **GR motion matching.** The real clip's camera path is in VGGT's arbitrary units and FlashWorld invents its own scene depth, so the same path gave 1.3–4.2× the real image motion. Rescaling translations moved render cameras off the generation path (holes, coverage 0.95). Instead the generated path is **played more slowly** (only its first fraction, resampled to 48 frames): poses stay on the path, coverage stays ≥ 0.98, and the per-clip speed is calibrated to match RC. Limitation: it can only slow a path down.
- **Attacks.** Blur exposure is calibrated once against the real clips' sharpness-vs-motion behaviour (the grid saturated at its upper end, 0.5). Noise is matched per clip to the paired real clip's noise level with *all* noise variances scaled together; scaling only the shot-noise gain left a read-noise/PRNU floor that was already louder than many real clips (117 of 288 clips pinned at the minimum gain, achieved noise 1.3–1.7× the real level), which is why the variants `noise`, `blur+noise`, `noisecal`, `blurcal+noisecal` are retired and ignored by the analysis.
- **Resolution control.** Real frames are shrunk from ~4K with an area filter, renders are produced at 704×480. The control re-renders GR/RR at 3× from the same worlds / paths / speeds and area-downscales them.
- **Calibration check.** `analysis.py` reports attacked-vs-real noise level / exposure-jitter ratios; use it before interpreting any attack result.
- **CPS-2 design.** CPS-1's features needed VGGT geometry and a one-class Mahalanobis on heavy-tailed features (several reach |300|), which scored ~0.5. CPS-2 measures motion by optical flow, adds temporal cues (auto-exposure / white-balance gain jitter, temporal vs. spatial noise, noise whiteness, chroma noise) and rank-normalises the features. The auto-exposure cues detect *generated* worlds but not renders of real scenes (a 3DGS fitted to real frames inherits their exposure changes); part of the spectrum cue is a resampling effect (it shrinks under the 3x supersampled control). Both facts are reported rather than hidden.
- **Exposure-aware attack.** `attacks.exposure_jitter` fakes exposure and white-balance jitter at the paired real clip's measured level, i.e. an attacker who knows the strongest new cue. Setting the random-walk sigma to the target under-shoots (the gain estimator attenuates an injected walk: measured 0.46-1.30x of the target on real clips), so `pipeline.calibrate_exposure_jitter` measures the attacked clip and rescales sigma (twice); afterwards 0.92-1.03x on typical clips, bounded below by the estimator's noise floor for clips with almost no real jitter.
- **Attack stage is parallel.** `build_variants` makes clips in a process pool (CPU only; the v15 stage took 90 min serially for 576 clips). The blur exposure is calibrated once in the parent.
- **Defender protocols.** Attack-aware training ("aug") is reported three ways: attack *seen*; *new combination* (components appear in other training attacks); *unseen components* (no training attack shares a component with it). Only the last is a statement about generalisation to a new attacker; the middle one is what a defender who trained on blur-only and noise-only attacks gets against blur+noise.
- **Tried and dropped: ISP-trace noise cues.** Cross-channel residual correlation, residual autocorrelation at lags 2/4 and the residual power-spectrum tilt separate real noise from white per-channel noise on raw frames (channel correlation 0.65 vs 0.03), but every clip, real or attacked, goes through the same H.264 yuv420p encode, which re-couples the colour channels: on the benchmark clips they added nothing against noise-matched attackers (dev, RR noise-attacked 0.53-0.55 with or without them). Not included.
- **Fair baselines and fusion (v17).** UnivFD/NPR with their released weights are zero-shot, so the same backbones also get a probe trained on the dev scenes (`embed.py`, `learned.ProbeClassifier`). On dev scenes (5-fold scene-grouped CV, clean clips, generated worlds / real-scene renders): zero-shot UnivFD 0.65/0.52, retrained CLIP probe 0.81/0.78, CPS-2 0.92/0.88, CPS-2 + CLIP 0.95/0.92; the 3x-supersampled control scores the same for the probe, so it does not use resampling. Against the matched blur+noise+exposure attacker (clean-trained) CPS-2 falls to 0.70/0.40 but the CLIP probe only to 0.76/0.68, and the fusion keeps 0.81/0.59 - the physics cues are what the attacker removes, the semantic/render-artifact features are not. Equal-weight fusion equals stacked fusion (<=0.02), so the simpler one is used.
- **Randomised-attacker training (RAT).** Fakes processed by the attack operators at RANDOM strengths (blur 0.15-0.6x motion, noise strength 0.02-0.6 log-uniform, exposure walk 2e-4..8e-3), never the calibrated attack, enlarge the training set (`nz-*` variants, `attacks.nuisance`, optical-flow motion so no geometry is needed). On dev (matched attackers unseen, clean-trained -> RAT; GR/RR, fusion): noise 0.87/0.65 -> 0.90/0.73, blur+noise 0.83/0.60 -> 0.88/0.73, blur+noise+exposure 0.82/0.59 -> 0.88/0.73, with clean 0.95/0.92 -> 0.93/0.91 (no clean cost, unlike training on the calibrated attack: clean RR 0.79). Remove the operators sharing a component with the evaluated attack and the gain largely disappears (RR 0.59-0.69), so it is a defence against the attacker's operator FAMILY, not against a new kind of attack. Those dev numbers used a narrow noise range (strength ~0.01 x lognormal, much weaker than the attacker's 0.001-0.33). With the final range (log-uniform 0.02-0.6), dev, fusion, GR/RR: clean 0.92/0.84 (clean-trained 0.95/0.92), noise 0.95/0.89, blur+noise 0.94/0.89, blur+noise+exposure 0.94/0.88; with the attack's components removed from the training operators 0.87/0.69, 0.84/0.66, 0.82/0.59 (= clean-trained). So RAT buys robustness to this operator family at a clean real-scene cost (0.92 -> 0.84), and none against a different kind of attack. The false-alarm test (real clips through the same operators) was not run locally; the notebook computes it on all scenes (`cps2_operators`, `cps2_operators_cv`) together with the SYM variant, so the claim made in the paper is the measured one.
- **Symmetric operator augmentation (real AND fake) did not help CPS-2 or the fusion.** Applying randomised blur/noise/exposure operators to real AND fake clips (so the operator carries no label) scored the same as no augmentation against matched attackers on dev (RR blur+noise 0.40 vs 0.35; unseen components 0.35), because a matched attacker leaves the 23 noise/blur cues with no information. Reported as a negative result.
- **Defender trade-off (dev scenes).** Putting attacks in the training set restores performance on those attacks but costs clean accuracy on real-scene renders (RR 0.83 to 0.66 with logistic regression, 0.81 to 0.70 with gradient boosting); a noise-invariant feature subset costs more (clean 0.92 to 0.76).
